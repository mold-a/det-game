# P02. Нормализация ответов и криптография (Python + JS)

---

Работаем по `CLAUDE.md`. Главный документ шага — `docs/02-architecture.md`, §2 и §3. Это фундамент: ошибка здесь сломает всю игру незаметно, поэтому тесты важнее скорости.

**Сделай:**

1. **Нормализация.**
   - `engine/normalize.py` и `site/assets/js/core/normalize.js` с одинаковым API: `normalize(type, value) → str | None` для всех типов из §2 (`None` / `null` — невалидный ввод). Для `multi`/`persons`/`order` вход — список ID.
   - `base()` реализуй посимвольно по категориям Unicode (L*, N* — оставить, остальное — пробел), а не через `\w`: в Python и JS `\w` различается.
   - `tests/vectors/normalize.json` — не меньше 60 случаев, написанных руками: кириллица и латиница, «ё», пробелы, табуляция и неразрывный пробел, пунктуация, эмодзи, дефисы, числа с ведущими нулями, время во всех форматах из таблицы и невалидное («24:00», «7:60», «12345», пусто), даты с годом и без, високосный год, перепутанный регистр ID.
   - Тесты Python и JS читают один и тот же файл векторов.

2. **Криптография.**
   - `engine/crypto.py`: `b64u_encode/decode`, `pbkdf2(password: bytes, salt: bytes, iterations) → 32 байта`, `hkdf(ikm, info: bytes) → 32 байта` (соль — 32 нулевых байта), `seal(key, plaintext: bytes, aad: str) → dict` (контейнер из §3.1), `open_(key, container) → bytes` (ошибка при неверном ключе/AAD).
   - `site/assets/js/core/crypto.js`: те же функции на Web Crypto, асинхронные, без сторонних библиотек. PBKDF2 и HKDF — через `deriveBits` (ключи этапов сохраняются в прогрессе как байты); ключи AES импортируются неэкспортируемыми.
   - Хелперы верхнего уровня (и там, и там): `answerKey(path, normalized, salt, iters)`, `stageSecret(n, pairs)`, `labInfo(object, type, basis, params)` — строки ровно по §3.3–3.6.
   - Проверка «защищённого контекста» в JS: `isCryptoAvailable()`.

3. **Векторы и кросс-тесты.**
   - `python -m engine vectors` → `tests/vectors/crypto.json`: PBKDF2 (3 случая, включая кириллический пароль), HKDF (2), контейнеры AES-GCM с разными AAD (3), записи-проверки ответа для единицы с 3 вариантами и паддингом до 8. Детерминированные nonce — **только** внутри генератора векторов, флагом.
   - `tests/js/crypto.test.mjs`: выводит те же ключи, расшифровывает контейнеры, проверяет, что неверный AAD и неверный ключ дают ошибку, находит верную запись среди паддинга.
   - Обратное направление: `tests/js/make_vectors.mjs` шифрует в JS, `tests/test_crypto_js_compat.py` вызывает его через Node (пропуск теста, если Node нет) и расшифровывает в Python.

4. **Замер.** `tests/js/bench_pbkdf2.mjs` печатает время PBKDF2 для 100 000, 150 000 и 300 000 итераций.

**Не делай:** не меняй правила нормализации и форматы из `docs/02-architecture.md` молча. Если правило кажется неудачным — опиши в отчёте и спроси.

**Готово, когда:**
- `python -m pytest` и `npm run test:js` зелёные;
- векторы нормализации — те же файлы для обеих сторон, без исключений «только для Python»;
- контейнер, созданный в Python, открывается в JS, и наоборот.

**Отчёт:** таблица покрытия векторов по типам, результаты замера PBKDF2, найденные расхождения между Python и JS и как они решены.
