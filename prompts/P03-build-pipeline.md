# P03. Сборщик: контент → зашифрованный `dist/`

---

Работаем по `CLAUDE.md`. Документы шага: `docs/02-architecture.md` (§3–5), `docs/03-content-format.md`, `docs/06-testing.md` (§2–3). Интерфейс пока минимальный — красивые страницы появятся в P04–P06. Сначала покажи план в чате (модули, порядок, как будешь тестировать) и дождись «ок».

**Сделай:**

1. **Загрузка и валидация.** Модели `pydantic` для всех файлов `content/`. Перекрёстные проверки: ID персонажей, документов, вариантов и объектов существуют; у обязательного вопроса ровно 3 подсказки; у `form` есть поля; `order` содержит все карточки ровно по разу; у объекта с `params` у каждого результата есть `params_answer`; страницы ссылаются на существующие документы. Ошибка = файл + путь до поля + что не так.
2. **Шаблоны.** Jinja2 `SandboxedEnvironment` + `StrictUndefined`. Объекты `c` (персонажи с методами `full/short/io/first/last(case)`, `g(m, f)`, полями `role`, `nick`, `age`) и `w` (мир). Склонение — библиотекой склонения ФИО с ручными исправлениями `forms`. `python -m engine names` печатает таблицу всех форм.
3. **Соли.** `engine/salts.lock.json` по §3.2: создаётся при первой сборке, дописывается при новых единицах, не пересоздаётся. `rotate-salts --yes` — с предупреждением про QR-коды.
4. **Ответы.** Рендер канона и вариантов → нормализация → раскрытие допусков времени → записи-проверки с паддингом и перемешиванием. Ключи этапов по §3.4.
5. **Пакеты.** `data/pack-1..4.json` по §3.5 (ключ пакета — через HKDF от секрета этапа, §3.4): вводное письмо, вопросы, записи, подсказки, соль этапа, документы этапа, объекты лаборатории этапа (`from_stage`), записи экспертиз. `data/public.json` — только открытые данные.
6. **Экспертизы** по §3.6, включая параметры с допусками и «атмосферные» результаты. Документы-результаты рендерятся из `content/documents/*.md` (`python-frontmatter` + `markdown-it-py`; front matter `form` определяет бланк — пока простой; `media:` — список файлов из `media/`, шифруются по §4а).
7. **Развязка** `data/finale.json` по §3.7.
8. **Страницы.** Для каждой `content/pages/<slug>`: открытая → обычный HTML; закрытая (`true`) → оболочка + `payload.json` на постоянном ключе; `password` → оболочка + контейнер на ключе от пароля. Медиа — по `docs/02-architecture.md` §4а: открытые копируются с хешем в имени, используемые только зашифрованным контентом — шифруются. Если медиафайла нет — заглушка-плейсхолдер, предупреждение в отчёте (не ошибка, кроме `--release`).
9. **HTML.** Временные минимальные шаблоны: `/`, `/lab/`, `/final/`, `/p/<slug>/` — с `noindex`, подключением будущих скриптов. `robots.txt`.
10. **`check`** — все пункты `docs/06-testing.md` §3, включая leak scan (целые слова, с раскрытием `\uXXXX`, без полей `n`/`c` и `.bin`), проверку медиа и `forbidden` у страниц. Итоговая таблица в конце.
10а. **`dump-answers`** → `tests/.answers.json`: для каждой единицы — отрендеренный канон и все варианты после нормализации, для экспертиз — объект, вид, основания, параметры; плюс `points`, `penalties`, `hints` из настроек. Только для тестов, файл в `.gitignore`.
11. **`--release`**: любая `TODO(content)`, отсутствующее медиа или пустой пароль облака — ошибка.
12. **Тесты:** валидация на испорченных копиях контента (минимум 8 случаев), стабильность солей между сборками, `check` на текущем контенте.

**Не делай:** не исправляй ответы и тексты в `content/`. Если нашёл ошибку в контенте — опиши в отчёте.

**Готово, когда:**
- `python -m engine build && python -m engine check` проходят на текущем контенте (с заглушками);
- leak scan специально ловит утечку: тест подкладывает в `dist/` строку с ответом и ожидает падение;
- повторная сборка без изменений контента даёт те же ключи этапов и страниц.

**Отчёт:** таблица из `check`, список `TODO(content)`, найденные ошибки контента, размер `dist/`.
