# 01. Правила игры (спецификация для сайта)

Сайт — единственный ведущий. Он не знает, что лежит в бумажных конвертах; он знает только вопросы, допустимые ответы (в зашифрованном виде), подсказки, результаты экспертиз и тексты. Все конкретные значения — в `content/`. Здесь описано поведение.

## 1. Как идёт игра

1. Команда открывает сайт на **главном устройстве** (ноутбук или планшет), вводит название команды, читает краткие правила.
2. Сайт говорит открыть папку дела (конверт №1). Начинается этап 1.
3. На каждом этапе есть **обязательные вопросы** и **бонусные**. Вопросы идут по одному. Ответив верно на все обязательные (и пройдя или пропустив бонусы этапа), команда получает сообщение «Откройте конверт №N» — ключ следующего этапа выдаётся сразу после последнего обязательного — и открывает вопросы, подсказки и экспертизы нового этапа.
4. Этапы: 1 → 2 → 3 → 4. Этап 4 — **финал**: вопросы идут по одному, каждый ответ блокируется после отправки.
5. После финала: итоговый счёт, ранг, разбор ответов и **развязка** — одна для всех.

### Поток этапа

В начале каждого этапа (для этапа 1 — после «Открыть дело» и окна-конверта) главный экран показывает письмо руководителя. **Вопросы этапа скрыты** за кнопкой «Перейти к вопросам» с подписью «Откройте, когда команда изучит все документы конверта». Нажатие открывает окно подтверждения «Перейти к вопросам этапа N? Документы можно изучать и дальше» («Перейти» / «Отмена»). После подтверждения вопросы этапа (обязательные, бонусные и подсказки внутри них) открываются — по одному (ниже); флаг хранится в прогрессе (`questionsOpen`, `docs/FORMATS.md` §7), назад вопросы не прячутся. Старые прогрессы без флага считаются открытыми для всех уже начатых этапов. На этапе 4 та же кнопка открывает блок «Перейти к финалу», а предупреждение финала (§8) показывается уже на `/final/`.

**Вопросы идут по одному, по порядку** (решение автора 23.10.2026). Порядок выводится из прогресса (решён или отвечен), отдельного поля в сохранении нет, старые сохранения работают.
- Обязательные идут в порядке из `content/`. Следующий появляется только после **верного** ответа на предыдущий. Нерешённые следующие не показываются вовсе, даже заголовком и номером: вместо них одна строка «Следующий вопрос откроется после ответа на текущий». Решённые остаются выше со штампом «Принято». Подсказки (кнопка покупки) — только у текущего вопроса; купленные у решённых остаются видны.
- Бонусные вопросы этапа идут **после последнего обязательного**, тоже по одному. Следующий появляется после ответа на предыдущий, **верного или нет** (у бонуса одна попытка).
- **Переход этапа.** Верный ответ на последний обязательный сразу даёт ключ следующего этапа. Если у этапа есть неотвеченные бонусы, окно «Откройте конверт №N» показывается не сразу: экран остаётся на пройденном этапе, идут его бонусы по одному, под ними кнопка «Пропустить бонусы и перейти к конверту №N». Окно появляется после ответа на последний бонус (или по кнопке «Пропустить»). Если бонусов нет или они отвечены — окно сразу. Состояние «конверт ещё не вскрыт» уже есть в прогрессе (`envelopeAck < stage`), поэтому после перезагрузки страницы экран возвращается к бонусам.
- Пропущенные бонусы прошлых этапов (и неотвеченные бонусы в старых сохранениях) остаются доступными в блоке «Этап N пройден» — по тем же правилам, по одному, — пока команда не начнёт финал.
- Финал (этап 4, `/final/`) идёт по одному и раньше (§8) — не менялся.

Онлайн-материалы из QR-кодов открываются на любом телефоне и не влияют на счёт.

## 2. Этапы

| Этап | Что открывается при старте этапа | Что нужно для перехода |
|---|---|---|
| 1 | Письмо, вопросы этапа 1 (после «Перейти к вопросам»), лаборатория (большинство предметов описи «ничего не выявляют») | Все обязательные вопросы этапа 1 |
| 2 | Сообщение «Откройте конверт №2», вводное письмо, вопросы, подсказки, экспертизы этапа 2 | Все обязательные вопросы этапа 2 |
| 3 | То же для конверта №3 | Все обязательные вопросы этапа 3 |
| 4 | То же для конверта №4; финальные вопросы | Отправка всех финальных ответов |

Вводное письмо этапа (от руководителя расследования) показывается при входе в этап и доступно повторно.

- Ключ следующего этапа выдаётся сразу после последнего верного обязательного ответа; окно «Откройте конверт №N» показывается после бонусов этого этапа или после «Пропустить бонусы» (см. «Поток этапа»). Неотвеченные бонусы прошлых этапов остаются доступными, пока команда не начнёт финал.
- Все вопросы этапа 4 — и финальные, и бонусные — задаются только на странице `/final/` и подчиняются правилам финала (§8).

## 3. Типы вопросов

| Тип | Ввод | Пример | Нормализация |
|---|---|---|---|
| `text` | Строка | Название вещества | см. `02-architecture.md` §2 |
| `time` | ЧЧ:ММ | Время ухода охранника | Приведение к `ЧЧ:ММ`; допуск задаётся вариантами |
| `date` | ДД.ММ.ГГГГ | Дата покупки билета | Приведение к `ГГГГ-ММ-ДД` |
| `number` | Число | Номер кассы | Только цифры |
| `choice` | Один вариант из списка | Почему опасно вещество | ID варианта |
| `multi` | Несколько вариантов | Чьё алиби подтверждено | Отсортированный список ID |
| `person` | Один персонаж из списка | Кто доставил в театр | ID персонажа |
| `persons` | Несколько персонажей | Кто ещё причастен | Отсортированный список ID |
| `order` | Перетаскивание карточек | Хронология вечера | ID в выбранном порядке |
| `document` | Один документ из полученных | Какой документ подтверждает | ID документа |
| `form` | Несколько полей любых типов выше | «Справка о погибшем» | Каждое поле отдельно |

Правила для списков:
- Варианты `choice` и `multi` показываются в порядке из `content/` (автор сам их перемешивает).
- Список персонажей для `person`/`persons` — из `content/stages.yaml` (поле `pool`), по умолчанию все лица дела, кроме служебных.
- Список документов для `document` — только документы, уже полученные командой: бумажные документы открытых этапов плюс результаты выполненных экспертиз. Это часть вопроса, а не навигация: отдельной панели «Документы дела» на сайте нет (переработка 21.10.2026), адреса онлайн-материалов игроки находят в бумажных документах (QR-код или напечатанный адрес) и на других страницах.
- `order`: карточки изначально перемешаны детерминированно (одинаково при каждой загрузке).
- `form`: вопрос засчитывается, только если верны **все** поля. Сайт не говорит, какое поле неверно.

## 4. Попытки и штрафы

- **Обязательные вопросы:** попыток сколько угодно. Каждая неверная — штраф `penalties.wrong_attempt` (по умолчанию −5).
- После `hints.auto_after_wrong` неверных попыток (по умолчанию 3) подсказка уровня 1 открывается **бесплатно**, если ещё не куплена.
- **Бонусные вопросы:** одна попытка. Верно — `points.bonus` (+15), неверно — 0, вопрос закрывается.
- **Финальные вопросы:** одна попытка каждый. Верно — `points.final` (+30).
- Пустой ответ и ответ неверного формата (например, «25:70» во времени) не считаются попыткой: сайт показывает подсказку по формату.
- Повтор уже отправленного неверного ответа не штрафуется повторно: сайт пишет «Этот ответ уже проверяли».

## 5. Подсказки

- У каждого обязательного вопроса три уровня: 1 — куда смотреть, 2 — что сопоставить, 3 — ответ.
- Покупаются строго по порядку. Цена: `hints.cost` = [10, 20, 40].
- Купленная подсказка остаётся видимой до конца игры.
- У бонусных и финальных вопросов подсказок нет.
- Перед покупкой — подтверждение с ценой («Подсказка 2 уровня: −20 баллов. Открыть?»).

## 6. Баллы и ранги

- Старт: 0. Счёт может уйти в минус.
- Счёт — сумма журнала событий (`score_log`): каждое начисление и списание с причиной и временем. Журнал виден команде.
- Ранги по итоговому счёту — `ranks` в `settings.yaml` (сейчас: до 119 — «Стажёр», 120–224 — «Следователь», от 225 — «Шерлок»; пороги пересчитаны 21.10 после бонусов s2.b2 и fb3).
- Максимум при текущем контенте: 9 бонусов × 15 + 5 финальных × 30 = 285 (бонусы: s1.b1; s2.b1, s2.b2; s3.b1–b3; на `/final/` — fb, fb2, fb3).

## 7. Лаборатория (экспертизы)

Экспертизы — единственный способ получить часть документов (результаты исследований, данные оператора, записи камер). Лаборатория в мире игры — независимый экспертный центр (`brands.lab_full`) с отдельным сайтом на `/lab/` (`docs/04`); команда — заказчик по договору следственного отдела.

Заявка:
1. **Объект исследования** — свободный текст: команда называет предмет так, как он назван в описи изъятого. Текст распознаётся среди объектов `expertise.objects`, доступных на текущем этапе (`from_stage ≤` последнего открытого этапа), алгоритмом из `docs/02` («Распознавание объекта»). В «описи» есть и нужные предметы, и пустышки из протоколов осмотра.
2. **Вид исследования** — из `expertise.types`.
3. **Основание** — документ из полученных командой (см. §3). Обязательно.
4. **Параметры** — только если у распознанного объекта они есть (например, дата, время и касса для камер вокзала); поля появляются, как только текст распознан.

Поведение (по порядку):
1. Текст объекта:
   - **не распознан** → «Такого предмета нет в описи изъятого. Его нельзя передать в лабораторию.» Без штрафа, в «Мои заявки» не попадает;
   - **неоднозначно** (лучших кандидатов несколько) → «Уточните, какой предмет вы передаёте: «А» или «Б».» Без штрафа. Названия кандидатов показываются: это предметы из описи, раскрывать тут нечего;
   - **распознан** → дальше. Те же три исхода сайт показывает под полем вживую, до отправки (`docs/04`).
2. Не выбран вид или основание, параметр в неверном формате → подсказка по формату, это не заявка и не штраф.
3. Комбинация (объект, вид, основание, параметры) проверяется по записям всех открытых этапов:
   - **есть запись** → «Заключение готово». Документ добавляется в «Мои заявки» и в полученные документы (основание следующих заявок и ответ на вопросы типа `document`). Результат без документа — короткий текст на фирменном листе центра;
   - **нет записи** → «Экспертиза ничего не выявила.» Штраф `penalties.lab_no_basis` (ключ прежний, смысл — «пустая экспертиза»).
4. Повтор той же комбинации (отпечаток — по id распознанного объекта, а не по тексту) не штрафуется повторно: «Такая заявка уже выполнялась», показывается прежний итог. Каждый запрос всё равно проверяется заново по всем открытым этапам; если результат есть на нескольких этапах — показывается самый поздний. Поэтому заявка, которая «ничего не выявила», после перехода этапа может дать заключение.
5. Чтобы правило 4 не противоречило правилу 3, сборка проверяет каждую запись результата этапа N: если объект доступен раньше этапа N, то каждое её основание — документ этапа N (`docs/02`, `docs/03`).
- У одной экспертизы может быть несколько допустимых оснований: любое из них подходит.
- «Мои заявки» — все заявки команды (кроме нераспознанных и неоднозначных) с датой и временем по часам браузера, распознанным названием объекта, видом, основанием, параметрами и итогом; заключения открываются отсюда.

## 8. Финал (этап 4)

- Вопросы показываются по одному, в порядке из `content/`.
- Ответ блокируется после отправки, вернуться нельзя. Сайт не говорит, верно ли, до конца финала.
- Баллы за финальные и бонусные вопросы этапа 4 записываются в журнал только после последнего ответа: счёт в шапке во время финала не меняется, иначе он выдал бы правильность.
- Перед первым вопросом — предупреждение: «Ответы финала нельзя изменить. Убедитесь, что изучили все материалы».
- Бонусные вопросы этапа 4 (если есть) идут последними, в порядке из `content/`.
- После последнего ответа: экран итогов — счёт, ранг, разбор всех вопросов игры (ответ команды → верный ответ), затем развязка.

## 9. Развязка

Одна для всех, независимо от ответов. Три части, по порядку, с кнопкой «Дальше»:
1. Признание исполнителя (протокол допроса).
2. Письмо погибшего крестнице (Марина — дочь Кирилла и крестница Воронцова, решение автора 20.10.2026).
3. Судьбы персонажей — по строке на каждого.

## 10. Прогресс и восстановление

- Прогресс хранится в браузере главного устройства и переживает перезагрузку.
- Кнопка «Сохранить прогресс в файл» и «Загрузить из файла» — на случай смены устройства или очистки браузера.
- Кнопка «Начать заново» — с двойным подтверждением.
- Если сайт пересобран с другими ответами, старый прогресс несовместим: сайт честно сообщает и предлагает начать заново.

## 11. Тексты интерфейса

Тон — служебная система следственного отдела: сухо, вежливо, без шуток. Юмор живёт в материалах дела, не в интерфейсе. Примеры:
- «Ответ принят. Откройте конверт №2».
- «Ответ не подтверждается материалами дела».
- «Экспертиза ничего не выявила». (Сайт лаборатории говорит от лица частного центра — вежливо-коммерческим тоном: «Передайте нам предмет из описи изъятого…».)
- «Этот ответ уже проверяли».
