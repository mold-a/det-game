# DEPLOY. Как выложить сайт игры

Инструкция для человека без опыта. Время — 1–2 часа в первый раз, плюс ожидание DNS (до суток).
Факты о хостингах проверены 2026-10-13 по официальной документации (ссылки — в конце). Цены и лимиты
меняются: перед выбором откройте ссылки и сверьте.

---

## 0. Что выкладывается

- Только папка `dist/` — результат `python -m engine release`. Он же лежит архивом `print/dist-<buildId>.zip`.
- **Никогда** не выкладывайте весь репозиторий: в `content/`, `print/`, `tests/.answers.json` — ответы.
- В `dist/` ответы только зашифрованы; это проверяет `python -m engine check` (leak scan).

Перед выкладкой:

```
python -m engine release
```

Команда собирает сайт в режиме релиза, проверяет его и делает архив. Она откажется работать, если:
- остались заглушки `TODO(content)`;
- нет медиафайлов (фото, аудио, видео в `media/`);
- не задан пароль облака;
- домен в `content/settings.yaml` всё ещё `example.ru`.

Домен выберите и впишите в `settings.yaml → domain` **до** сборки и печати QR-кодов: QR ведут на `https://<домен>/p/…`, после печати домен менять нельзя.

## 1. Требования к хостингу

| Требование | Почему |
|---|---|
| Статические файлы (без сервера, без PHP и баз данных) | Сайт — папка файлов, вся логика в браузере |
| Свой домен | Он напечатан в QR-кодах; бесплатный адрес хостинга может смениться |
| HTTPS с действующим сертификатом | Без HTTPS браузер не даёт криптографию (`crypto.subtle`), игра не запустится |
| Сайт в **корне** домена (`https://домен/`, не `https://домен/игра/`) | Все ссылки на сайте абсолютные от корня (FORMATS F18) |
| Файл до ~26 МБ | Самый большой файл — зашифрованное видео `video` (видео ≤ 25 МБ + 28 байт) |
| Настраиваемый заголовок `Cache-Control` | Иначе после обновления телефоны держат старые файлы (см. §4) |
| Открывается из России у игроков (мобильный интернет разных операторов) | Игроки сканируют QR телефоном |

Размер всего сайта сейчас — около 1 МБ без медиа; с медиа — до ~30–40 МБ. Нагрузка — одна семья: трафик ничтожный.

## 2. Варианты хостинга

| | Yandex Object Storage | Netlify | Cloudflare Pages |
|---|---|---|---|
| Доступ из России | Российский сервис — работает | **Нет данных — проверить перед выбором** | **С июня 2025 года российские операторы ограничивают Cloudflare** (страницы не догружаются) — для игроков в России **не рекомендуется** |
| Лимит на файл | Нет практического (больше видео) | Официально нет; документация предупреждает, что при ручной загрузке файлы > 10 МБ могут «зависать» — грузить через консольную утилиту | **25 МиБ** (≈ 26,2 МБ) на файл |
| Заголовки кеширования | Задаются при загрузке (`--cache-control`) | Файл `_headers` — сборка кладёт его в `dist/` | Файл `_headers` — тот же |
| Цена | Платно по факту: первый 1 ГБ хранения и 100 ГБ исходящего трафика в месяц бесплатно; дальше ~2,38 ₽/ГБ хранения и ~1,68 ₽/ГБ трафика. Нужен платёжный аккаунт | Бесплатный план: 300 кредитов в месяц; выкладка — 15 кредитов, трафик — 20 кредитов за ГБ. Для семьи хватит | Бесплатно |
| Свой домен | Имя бакета = домен; поддомен — CNAME, домен второго уровня — ANAME (нужен Cloud DNS) | Поддомен — CNAME; домен второго уровня — ALIAS/ANAME или A-запись | Поддомен — CNAME; домен второго уровня — только если DNS домена перенесён в Cloudflare |
| HTTPS | Бесплатный Let's Encrypt через Certificate Manager | Автоматически | Автоматически |

**Рекомендация:** игроки в России → **Yandex Object Storage** (аналоги — объектные хранилища Selectel, Timeweb Cloud, VK Cloud; принцип тот же, команды другие). Netlify — запасной вариант, если проверка с телефонов игроков прошла. Cloudflare Pages — только если игроки не в России.

**GitHub Pages не подходит:** заголовки кеширования там не настраиваются, для приватного репозитория нужен платный план, а сам GitHub с мая 2026 года открывается из России с перебоями.

Проще всего взять **поддомен**, например `game.ваш-домен.ru`: для него у всех трёх хостингов достаточно одной записи CNAME.

### 2.1. Yandex Object Storage (рекомендуется для России)

Понадобится аккаунт Yandex Cloud с платёжным аккаунтом (банковская карта) и утилита `yc`
(установка — в документации Yandex Cloud, раздел «CLI»).

1. **Бакет.** Консоль Yandex Cloud → Object Storage → «Создать бакет».
   - Имя бакета **ровно как домен**: `game.ваш-домен.ru`.
   - Доступ на чтение объектов — **публичный**. Без этого сайт отвечает 403.
2. **Хостинг.** В бакете: «Веб-сайт» → «Хостинг».
   - Главная страница — `index.html`.
   - Страница ошибки — можно оставить пустой.
3. **DNS.** У регистратора домена создайте запись:
   - поддомен: `CNAME`, имя `game`, значение `game.ваш-домен.ru.website.yandexcloud.net`;
   - домен второго уровня (`ваш-домен.ru`): CNAME нельзя. Перенесите DNS в Yandex Cloud DNS (серверы `ns1.yandexcloud.net`, `ns2.yandexcloud.net`) и создайте запись `ANAME` со значением `ваш-домен.ru.website.yandexcloud.net`.
4. **HTTPS.**
   - Certificate Manager → «Добавить сертификат» → «Сертификат от Let's Encrypt» → домен `game.ваш-домен.ru`.
   - Подтвердите владение доменом записью, которую покажет консоль (DNS-проверка, запись `_acme-challenge`).
   - Когда сертификат выпущен: бакет → «Безопасность» → HTTPS → источник «Certificate Manager» → выберите сертификат. Переадресация с HTTP на HTTPS включается сама.
5. **Загрузка с правильными заголовками.** Из корня репозитория, после `python -m engine release`. Сначала добавьте `--dryrun` и посмотрите, какие файлы попадут в каждую команду; затем выполните без него:

   ```
   # всё, кроме медиа и шрифтов: проверять обновления при каждом открытии
   yc storage s3 cp dist/ s3://game.ваш-домен.ru/ --recursive --exclude "m/*" --exclude "assets/fonts/*" --exclude "_headers" --cache-control "no-cache"
   # медиа и шрифты: имена не меняются при той же сборке, кешировать надолго
   yc storage s3 cp dist/m/ s3://game.ваш-домен.ru/m/ --recursive --cache-control "public, max-age=31536000, immutable"
   yc storage s3 cp dist/assets/fonts/ s3://game.ваш-домен.ru/assets/fonts/ --recursive --cache-control "public, max-age=31536000, immutable"
   ```

   Файл `_headers` в Object Storage не нужен: заголовки задаёт `--cache-control`.
6. Проверьте, что `.json` отдаются с типом `application/json`, а `.woff2` — `font/woff2`: `curl -sI https://game.ваш-домен.ru/data/public.json`. Утилита определяет MIME-тип сама; если тип неверный — перезалейте файл с `--content-type`.

### 2.2. Netlify

Нужен Node.js (уже стоит для тестов проекта).

1. Зарегистрируйтесь на netlify.com.
2. В терминале из корня репозитория:

   ```
   npx netlify-cli login
   npx netlify-cli deploy --dir dist          # пробная выкладка: даст временную ссылку
   npx netlify-cli deploy --dir dist --prod   # основная выкладка
   ```

   При первом запуске утилита предложит создать сайт — согласитесь.

   Загружайте через утилиту, а не перетаскиванием папки в браузер. Документация Netlify предупреждает, что ручная загрузка файлов больше 10 МБ может «зависнуть», а видео — до 25 МБ.
3. **Заголовки.** Файл `dist/_headers` создаёт сборка; Netlify подхватывает его сам.
4. **Домен.** Site configuration → Domain management → Add a domain.
   - Поддомен: у регистратора запись `CNAME` `game` → `<имя-сайта>.netlify.app`.
   - Домен второго уровня: `ALIAS`/`ANAME` → `apex-loadbalancer.netlify.com`. Если регистратор так не умеет — запись `A` → `75.2.60.5`.
5. **HTTPS.** Netlify выпускает сертификат Let's Encrypt сам после того, как DNS заработает. Статус — в разделе HTTPS настроек домена.
6. **Бюджет.** Бесплатный план — 300 кредитов в месяц. Одна выкладка — 15 кредитов, 1 ГБ трафика — 20 кредитов. Не выкладывайте десятки раз подряд. Видео скачивается с каждого телефона, открывшего страницу `video`.

### 2.3. Cloudflare Pages (если игроки не в России)

1. Зарегистрируйтесь на cloudflare.com → Workers & Pages → Create → Pages → «Upload assets» (Direct Upload).
2. Загрузите содержимое `dist/` (или архив). Либо через утилиту:

   ```
   npx wrangler pages deploy dist --project-name zakulisami
   ```

   Ограничение — 25 МиБ на файл: видео держите не больше 25 МБ.
3. **Заголовки.** `dist/_headers` подхватывается автоматически.
4. **Домен.** Проект → Custom domains → Set up a domain. Сначала добавьте домен здесь, потом создайте запись — иначе возможна ошибка 522.
   - Поддомен: `CNAME` → `<проект>.pages.dev`.
   - Домен второго уровня: только если DNS домена перенесён в Cloudflare.
5. **HTTPS** выпускается автоматически.

## 3. Привязка домена: общее

- Какие записи нужны — см. вариант выше. Удалите старые записи `A`/`CNAME` с тем же именем, если они есть.
- Сколько ждать: обычно от нескольких минут до нескольких часов; хостинги предупреждают — до суток.
- Как проверить DNS: `nslookup game.ваш-домен.ru` должен показать адрес хостинга (или CNAME на него).
- Как проверить HTTPS:
  - откройте `https://game.ваш-домен.ru/` — замок в адресной строке, без предупреждений;
  - `curl -sI https://game.ваш-домен.ru/` — ответ `200`;
  - `http://…` должен переадресовывать на `https://`.
- Если сертификат «не выпускается»: проверьте, что DNS уже указывает на хостинг, и что у домена нет записи `CAA`, которая запрещает Let's Encrypt.

## 4. Заголовки кеширования

По FORMATS §9.1:

| Путь | `Cache-Control` | Почему |
|---|---|---|
| HTML (`/`, `/lab/`, `/final/`, `/p/*`), `/data/*`, `/assets/js/*`, `/assets/css/*`, `robots.txt` | `no-cache` | Имена не меняются между сборками; браузер должен перепроверять файл при каждом открытии |
| `/assets/fonts/*`, `/m/*` | `public, max-age=31536000, immutable` | Шрифты не меняются; у медиа в имени хеш содержимого |
| всё | `X-Robots-Tag: noindex, nofollow` | Сайт не должен попасть в поисковики (плюс `robots.txt` и `<meta name="robots">`) |

Файл `dist/_headers` (Netlify, Cloudflare Pages) создаёт `python -m engine build`. Правила в нём записаны отдельно для каждого пути, без общего `/*` для `Cache-Control`: оба хостинга склеивают значения совпавших правил, и `no-cache` смешался бы с `immutable`. Для Object Storage те же значения задаются флагом `--cache-control` при загрузке (§2.1).

Проверка:

```
curl -sI https://game.ваш-домен.ru/data/public.json | grep -i cache-control      # no-cache
curl -sI https://game.ваш-домен.ru/assets/fonts/pt-sans-cyrillic-400-normal.woff2 | grep -i cache-control  # immutable
```

## 5. Обновление сайта

- Обновлять можно **до** начала игры: `python -m engine release` → загрузить `dist/` тем же способом.
- **Во время игры не пересобирайте и не перевыкладывайте:**
  - любое изменение ответов, вопросов или их порядка меняет ключи этапов (PLAN R8);
  - новая единица меняет `saltsId`, и сохранённый в браузере прогресс команды станет «несовместим со сборкой» — команде придётся начинать заново;
  - при загрузке часть файлов уже новая, часть ещё старая; телефон, открывший сайт в эту минуту, может получить пакет, который не расшифруется.
- `python -m engine rotate-salts --yes` меняет ключи закрытых страниц: после этого **все напечатанные QR-коды перестают работать**, их нужно перепечатать (`python -m engine qr`).
- Если что-то сломалось в день игры — играйте по «Аварийному конверту» (`print/answers.pdf`), а не чините сайт на ходу.

## 6. Проверка после выкладки

1. На компьютере: открыть `https://домен/`, начать игру, ответить на один вопрос. В консоли браузера нет ошибок; в «Сети» нет запросов к чужим доменам.
2. С телефона **по мобильному интернету** (Wi-Fi выключить), желательно у 2–3 разных операторов:
   - открывается главная страница, проверка ответа занимает меньше секунды;
   - отсканировать **каждый** напечатанный QR-код с листа `print/qr/sheet.pdf`: открытые страницы показываются, закрытые расшифровываются (а не «Ссылка повреждена»);
   - облако открывается паролем из записки 4-13;
   - видео и аудио воспроизводятся (iPhone и Android).
3. `https://домен/robots.txt` — `Disallow: /`.
4. Полный список — `docs/CHECKLIST.md`.
