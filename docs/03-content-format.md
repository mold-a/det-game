# 03. Формат контента (`content/`)

Весь сюжет — здесь. Код не содержит ни имён, ни ответов, ни текстов. Сборщик валидирует каждый файл схемой (pydantic) и падает с понятной ошибкой: файл, путь до поля, что не так.

```
content/
  settings.yaml      параметры игры и криптографии
  world.yaml         город, театр, вымышленные бренды, даты
  characters.yaml    персонажи: имена, пол, фото, формы имён
  documents.yaml     реестр всех материалов дела
  stages.yaml        этапы, вопросы, ответы, подсказки
  expertise.yaml     лаборатория: объекты, виды, результаты
  finale.yaml        развязка
  pages/             контент вымышленных страниц (YAML + Markdown)
  chats/             переписки и уведомления для «скриншотов» телефона (печать, P07)
  documents/         тексты онлайн-документов: результаты экспертиз, развязка (Markdown)
```

## 1. Шаблоны и имена

Все строки контента — шаблоны Jinja2 (песочница `SandboxedEnvironment`, `StrictUndefined`: опечатка в имени переменной — ошибка сборки).

Доступно в шаблонах:

| Выражение | Результат (пример) |
|---|---|
| `{{ c.zavyalov.full() }}` | Завьялов Юрий Викторович |
| `{{ c.zavyalov.full('gen') }}` | Завьялова Юрия Викторовича |
| `{{ c.zavyalov.short() }}` | Завьялов Ю. В. |
| `{{ c.zavyalov.io() }}` | Юрий Викторович |
| `{{ c.zavyalov.first('dat') }}` | Юрию |
| `{{ c.zavyalov.last('ins') }}` | Завьяловым |
| `{{ c.oleg.g('ушёл', 'ушла') }}` | по полу персонажа |
| `{{ c.voroncov.familiar }}` | Ваня (дружеское имя, не склоняется; см. §3) |
| `{{ w.city }}`, `{{ w.theater.short }}` | Верхнеречинск, ВОДТ |

Падежи: `nom`, `gen`, `dat`, `acc`, `ins`, `pre`. Склонение — библиотекой склонения ФИО (например, `pytrovich`; если не подходит — предложи альтернативу) с ручными исправлениями в `characters.yaml → forms`. Команда `python -m engine names` печатает таблицу всех форм всех персонажей для вычитки.

## 2. `settings.yaml`

```yaml
game_id: zakulisami        # ключ localStorage, латиница
title: "За кулисами правды"
domain: "https://example.ru"   # для QR-кодов
default_year: 2026
crypto:
  iter_answer: 150000
  iter_stage: 300000
  entries_pad: 8
points: { bonus: 15, final: 30 }
penalties: { wrong_attempt: -5, lab_no_basis: -5 }
hints: { cost: [10, 20, 40], auto_after_wrong: 3 }
ranks:
  - { min: null, max: 99,   name: "Стажёр" }
  - { min: 100,  max: 180,  name: "Следователь" }
  - { min: 181,  max: null, name: "Шерлок" }
leak_watchlist: ["…"]       # строки, которых не должно быть в dist/ в открытом виде
```

**Пути.** Все пути к текстам в `content/` (`body`, `confession`, `letter`) — относительно `content/`. Все пути к медиа (`photo`, `avatar`, `audio`, `video`) — относительно `media/`.

## 3. `characters.yaml`

```yaml
characters:
  - id: zavyalov            # латиница, используется в ответах и шаблонах
    working: "Юрий Завьялов"  # рабочее имя роли — как в таблице персонажей; ключ для import-cast
    role: "Художественный руководитель"
    importance: key         # key | secondary | service | background
    last: "Завьялов"
    first: "Юрий"
    middle: "Викторович"    # может быть пустым
    nick: null              # прозвище, если есть («Мастер»)
    gender: m               # m | f — для склонения и c.X.g()
    age: 58
    photo: "portraits/zavyalov.jpg"   # путь в media/, может отсутствовать
    in_pool: true           # участвует в списках персонажей по умолчанию
    forms:                  # необязательные ручные исправления склонения
      last: { gen: "Завьялова" }
    familiar: "Юра"         # необязательно: дружеское/домашнее имя
    cast: true              # по умолчанию true; false — import-cast не трогает
    father: null            # необязательно: ID отца — фамилия и отчество выводятся от него
```

Необязательные поля:

- **`father: <id>`** — фамилия и отчество персонажа всегда выводятся от отца
  (`engine/names.py`: `surname_for(father_last, gender)`, `patronymic_for(father_first, gender)`).
  Сборка сверяет `last` и `middle` с выведенными с учётом пола персонажа; расхождение — ошибка
  с ожидаемой формой. Отец должен существовать, быть мужского пола (`gender: m`) и не совпадать
  с самим персонажем. Если у отца в `last`/`first` заглушка `TODO(content)` — соответствующая
  часть не сверяется. Правила: фамилия м→ж `-ов/-ев/-ёв/-ин/-ын` → `+а`,
  `-ский/-цкий/-ской/-цкой` → `-ская/-цкая`, прочие окончания (`-ич`, `-ко`, `-ых`, `-их`,
  гласная, `ь`, `-ой`…) не меняются, двойная фамилия — по частям; отчество: Иван → Иванович/Ивановна,
  Сергей/Николай → -евич/-евна, Юрий → Юрьевич, Дмитрий/Георгий → -иевич, Игорь → Игоревич,
  особые: Илья → Ильич/Ильинична, Никита → Никитич/Никитична, Фома, Кузьма, Лука, Савва, Павел,
  Лев, Пётр, Яков, Михаил. Для имени, где правило неоднозначно (прочие на гласную и т. п.),
  сборка падает с просьбой указать отчество вручную. Если правило ошибается, правильная форма
  задаётся в `forms.<last|middle>.nom` (и в `last`/`middle`) — она важнее правила.
  `python -m engine names` помечает выведенные от отца части значком `↑`.

  ```yaml
  - id: marina
    father: voroncov        # Воронцов Иван Сергеевич
    last: "Воронцова"       # = surname_for("Воронцов", "f")
    first: "Марина"
    middle: "Ивановна"      # = patronymic_for("Иван", "f")
    gender: f
  ```

- **`familiar: "Ваня"`** — дружеское/домашнее имя, как зовут персонажа близкие.
  В шаблонах — `{{ c.voroncov.familiar }}`, не склоняется. Если поле не задано, обращение к нему —
  ошибка сборки «у персонажа «X» нет familiar». Пустая строка — ошибка.

- **`cast: false`** — вымышленный персонаж (не родственник): `import-cast` (P09) его не трогает,
  рабочее имя остаётся. По умолчанию `cast: true`.

  ```yaml
  - id: kovalev
    working: "Сержант Ковалёв"
    cast: false
  ```

## 4. `documents.yaml` — реестр материалов

```yaml
documents:
  - { id: "1-03", title: "Карта вызова скорой медицинской помощи", stage: 1, kind: paper }
  - { id: "1-12", title: "Страница М. А. Громова в соцсети «Круг»", stage: 1, kind: online, page: gromov }
  - { id: "2-01", title: "Заключение эксперта: ингалятор", stage: 2, kind: lab }
```

- `kind: paper` — лежит в конверте `stage`; сайт только знает о нём (для списков и оснований). Бумажный документ с QR-кодом на страницу — `kind: paper` + `page`.
- `kind: online` — страница сайта; `page` — slug из `content/pages/`.
- `kind: lab` — выдаётся только лабораторией; появляется у команды после успешного запроса.
- Названия документов `stage > 1` попадают только в зашифрованные пакеты.

## 5. `stages.yaml`

```yaml
stages:
  - n: 1
    envelope: 1
    intro: |                 # вводное письмо этапа (Markdown + шаблон)
      …
    on_complete: "Ответ принят. Откройте конверт №2."
    questions:
      - id: q1
        kind: mandatory       # mandatory | bonus | final
        type: form
        prompt: "Справка о погибшем"
        fields:
          - id: time
            type: time
            label: "Время констатации смерти"
            answer: { canon: "21:18", tolerance_min: 0 }
          - id: disease
            type: text
            label: "Хронические заболевания"
            answer: { canon: "астма", variants: ["бронхиальная астма"] }
        hints:
          - "…"   # уровень 1
          - "…"   # уровень 2
          - "…"   # уровень 3 — ответ
```

Правила:
- Путь единицы: `s<n>.<question.id>` или `s<n>.<question.id>.<field.id>`. Он участвует в криптографии — после выдачи QR и начала игр не переименовывать.
- `answer.canon` — канонический ответ (до нормализации; сборщик нормализует). `variants` — дополнительные допустимые формы. Для `time` — `tolerance_min` раскрывается в варианты. Для `choice`/`person`/`document` — ID; для `multi`/`persons` — список ID.
- `options` для `choice`/`multi`: список `{id, text}`. `pool` для `person`/`persons`: список ID персонажей или `default`.
- `kind: final` — только в этапе 4, порядок вопросов = порядок показа. Бонус этапа 4 (`kind: bonus`) задаётся на странице финала последним, по правилам финала.
- `leak_scan: false` у единицы — не искать её ответ в `dist/` (например, если время законно встречается в открытых материалах). Ставить осознанно.

Сборщик проверяет: у обязательного вопроса есть 3 подсказки; ID ответов существуют среди вариантов, персонажей или документов; у `form` есть поля; ответы `order` содержат все карточки ровно по разу.

## 6. `expertise.yaml`

```yaml
objects:
  - { id: inhaler, title: "Ингалятор погибшего" }
  - id: station_cam
    title: "Камеры железнодорожного вокзала"
    from_stage: 4           # показывать в списке с этапа 4 (по умолчанию 1); списки этапов 2–4 — в пакетах
    params:                 # параметры запроса — у объекта
      - { id: date, type: date, label: "Дата" }
      - { id: time, type: time, label: "Время" }
      - { id: window, type: number, label: "Номер кассы" }
types:
  - { id: chem, title: "Химическое исследование" }
results:
  - id: inhaler-chem
    object: inhaler
    types: [chem, content]  # любой из видов подходит
    stage: 2                # открывается с этапа 2
    bases: ["1-03", "1-08", "2-02"]
    doc: "2-01"             # ID документа из documents.yaml
    body: "documents/2-01.md"
  - id: station-video
    object: station_cam
    types: [video]
    stage: 4
    bases: ["3-07"]
    params_answer:
      date: { canon: "30.10.2026" }
      time: { canon: "14:37", tolerance_min: 7 }
      window: { canon: "2" }
    doc: "4-08"
    body: "documents/4-08.md"
```

- Если у объекта есть `params`, у каждого его результата должен быть `params_answer` со всеми параметрами. Сборщик раскрывает допуски и перемножает варианты (следить за числом комбинаций: предупреждение при > 200 на результат).
- Результат без `doc` — «атмосферный»: короткий текст в `text`, документ не добавляется, штрафа нет.

## 6а. Дополнительные поля вопросов

- `help` — пояснение под вопросом (как понимать формулировку), видно всегда.
- `items` — карточки для `order`: `{id, text}`; ответ — список ID в верном порядке.
- `leak_scan: false` — см. §5.

## 8. `pages/`

Одна папка на страницу: `pages/<slug>/page.yaml` (метаданные и структурированный контент: посты, записи, файлы облака) и при необходимости `*.md` для длинных текстов. Схема каждой страницы — в `docs/04-pages.md`. Поле `locked`: `false` — открытая страница; `true` — только по QR с ключом во фрагменте ссылки; `password` — по паролю из поля `password` (облако). Поле `doc` связывает страницу с документом из реестра. Поле `qr_label` — подпись под QR-кодом на печатной карточке (что видят игроки, без спойлеров). Поле `forbidden` (на верхнем уровне `page.yaml`) — слова, которых не должно быть в тексте страницы (сборщик проверяет).
