# 03. Формат контента (`content/`)

Весь сюжет — здесь. Код не содержит ни имён, ни ответов, ни текстов. Сборщик валидирует каждый файл схемой (pydantic) и падает с понятной ошибкой: файл, путь до поля, что не так.

```
content/
  settings.yaml      параметры игры и криптографии
  world.yaml         город, театр, вымышленные бренды, даты
  characters.yaml    персонажи: имена, пол, фото, формы имён
  documents.yaml     реестр всех материалов дела
  stages.yaml        этапы, вопросы, ответы, подсказки
  expertise.yaml     лаборатория: опись предметов (алиасы), виды, результаты
  lab.yaml           тексты сайта лаборатории «Призма»: о центре, контакты, услуги
  finale.yaml        развязка
  pages/             контент вымышленных страниц (YAML + Markdown)
  chats/             переписки и уведомления для «скриншотов» телефона (печать, P07)
  documents/         тексты онлайн-документов: результаты экспертиз, развязка (Markdown)
  paper/             тексты бумажных документов конвертов 1–4 — только печать (Markdown)
```

## 1. Шаблоны и имена

Все строки контента — шаблоны Jinja2 (песочница `SandboxedEnvironment`, `StrictUndefined`: опечатка в имени переменной — ошибка сборки).

Доступно в шаблонах:

| Выражение | Результат (пример) |
|---|---|
| `{{ c.zavyalov.full() }}` | Завьялов Юрий Викторович |
| `{{ c.zavyalov.full('gen') }}` | Завьялова Юрия Викторовича |
| `{{ c.zavyalov.short() }}` | Завьялов Ю. В. |
| `{{ c.zavyalov.io() }}` | Юрий Викторович |
| `{{ c.zavyalov.first('dat') }}` | Юрию |
| `{{ c.zavyalov.last('ins') }}` | Завьяловым |
| `{{ c.oleg.g('ушёл', 'ушла') }}` | по полу персонажа |
| `{{ c.voroncov.familiar }}` | Ваня (дружеское имя, не склоняется; см. §3) |
| `{{ w.city }}`, `{{ w.theater.short }}` | Верхнеречинск, ВОДТ |

Падежи: `nom`, `gen`, `dat`, `acc`, `ins`, `pre`. Склонение — библиотекой склонения ФИО (например, `pytrovich`; если не подходит — предложи альтернативу) с ручными исправлениями в `characters.yaml → forms`. Команда `python -m engine names` печатает таблицу всех форм всех персонажей для вычитки.

## 2. `settings.yaml`

```yaml

title: "За кулисами правды"

default_year: 2026

  iter_answer: 150000
  iter_stage: 300000
  entries_pad: 8
points: { bonus: 15, final: 30 }
penalties: { wrong_attempt: -5, lab_no_basis: -5 }
hints: { cost: [10, 20, 40], auto_after_wrong: 3 }
ranks:
  - { min: null, max: 99,   name: "Стажёр" }
  - { min: 100,  max: 180,  name: "Следователь" }
  - { min: 181,  max: null, name: "Шерлок" }
print:                       # бумага конвертов (python -m engine paper, docs/05 §4); всё необязательно
  duplex: true               # двусторонняя печать: документ и каждый протокол опроса — с нечётной страницы
  blank_back: "Оборот не заполнен"   # пометка на пустом обороте ("" — чистый)
  fit: { last_page_min: 0.15, scales: [0.97, 0.94, 0.91, 0.88] }  # подгонка висячих строк
leak_watchlist: ["…"]       # строки, которых не должно быть в dist/ в открытом виде
```

**Пути.** Все пути к текстам в `content/` (`body`, `confession`, `letter`) — относительно `content/`. Все пути к медиа (`photo`, `avatar`, `audio`, `video`) — относительно `media/`.

## 3. `characters.yaml`

```yaml
characters:
  - id: zavyalov            # латиница, используется в ответах и шаблонах
    working: "Юрий Завьялов"  # рабочее имя роли — как в таблице персонажей; ключ для import-cast
    role: "Художественный руководитель"
    importance: key         # key | secondary | service | background
    last: "Завьялов"
    first: "Юрий"
    middle: "Викторович"    # может быть пустым
    nick: null              # прозвище, если есть («Мастер»)
    gender: m               # m | f — для склонения и c.X.g()
    age: 58
    photo: "portraits/zavyalov.jpg"   # путь в media/, может отсутствовать
    in_pool: true           # участвует в списках персонажей по умолчанию
    forms:                  # необязательные ручные исправления склонения
      last: { gen: "Завьялова" }
    familiar: "Юра"         # необязательно: дружеское/домашнее имя
    cast: true              # по умолчанию true; false — import-cast не трогает
    father: null            # необязательно: ID отца — фамилия и отчество выводятся от него
```

Необязательные поля:

- **`father: <id>`** — фамилия и отчество персонажа всегда выводятся от отца
  (`engine/names.py`: `surname_for(father_last, gender)`, `patronymic_for(father_first, gender)`).
  Сборка сверяет `last` и `middle` с выведенными с учётом пола персонажа; расхождение — ошибка
  с ожидаемой формой. Отец должен существовать, быть мужского пола (`gender: m`) и не совпадать
  с самим персонажем. Если у отца в `last`/`first` заглушка `TODO(content)` — соответствующая
  часть не сверяется. Правила: фамилия м→ж `-ов/-ев/-ёв/-ин/-ын` → `+а`,
  `-ский/-цкий/-ской/-цкой` → `-ская/-цкая`, прочие окончания (`-ич`, `-ко`, `-ых`, `-их`,
  гласная, `ь`, `-ой`…) не меняются, двойная фамилия — по частям; отчество: Иван → Иванович/Ивановна,
  Сергей/Николай → -евич/-евна, Юрий → Юрьевич, Дмитрий/Георгий → -иевич, Игорь → Игоревич,
  особые: Илья → Ильич/Ильинична, Никита → Никитич/Никитична, Фома, Кузьма, Лука, Савва, Павел,
  Лев, Пётр, Яков, Михаил. Для имени, где правило неоднозначно (прочие на гласную и т. п.),
  сборка падает с просьбой указать отчество вручную. Если правило ошибается, правильная форма
  задаётся в `forms.<last|middle>.nom` (и в `last`/`middle`) — она важнее правила.
  `python -m engine names` помечает выведенные от отца части значком `↑`.

  ```yaml
  - id: marina
    father: voroncov        # Воронцов Иван Сергеевич
    last: "Воронцова"       # = surname_for("Воронцов", "f")
    first: "Марина"
    middle: "Ивановна"      # = patronymic_for("Иван", "f")
    gender: f
  ```

- **`familiar: "Ваня"`** — дружеское/домашнее имя, как зовут персонажа близкие.
  В шаблонах — `{{ c.voroncov.familiar }}`, не склоняется. Если поле не задано, обращение к нему —
  ошибка сборки «у персонажа «X» нет familiar». Пустая строка — ошибка.

- **`cast: false`** — вымышленный персонаж (не родственник): `import-cast` (P09) его не трогает,
  рабочее имя остаётся. По умолчанию `cast: true`.

  ```yaml
  - id: kovalev
    working: "Сержант Ковалёв"
    cast: false
  ```

## 4. `documents.yaml` — реестр материалов

```yaml
documents:
  - { id: "1-03", title: "Карта вызова скорой медицинской помощи", stage: 1, kind: paper }
  - { id: "1-12", title: "Страница М. А. Громова в соцсети «Круг»", stage: 1, kind: paper, page: gromov }
  - { id: "4-01", title: "Облачное хранилище погибшего", stage: 4, kind: online, page: cloud }
  - { id: "2-01", title: "Заключение эксперта: ингалятор", stage: 2, kind: lab }
```

- `kind: paper` — лежит в конверте `stage`; сайт только знает о нём (для списков и оснований). Бумажный документ с QR-кодом на страницу — `kind: paper` + `page`.
- `kind: online` — страница сайта без бумажного носителя; `page` — slug из `content/pages/`. На главном экране списка документов больше нет: игроки находят страницы сами, по QR-кодам и ссылкам. Сейчас так оформлен только `4-01` (облако): на него ведёт записка `4-13` с QR-кодом. Онлайн-документы, которым нужна бумага, — `kind: paper` + `page` (`1-12`, `1-13`, как `2-09`): лист с QR-кодом и коротким адресом; текст — `content/paper/<id>.md` (нет файла — `TODO(content)` при сборке, не ошибка).
- `kind: lab` — выдаётся только лабораторией; появляется у команды после успешного запроса.
- Названия документов `stage > 1` попадают только в зашифрованные пакеты.

## 5. `stages.yaml`

```yaml
stages:
  - n: 1
    envelope: 1
    intro: |                 # вводное письмо этапа (Markdown + шаблон)
      …
    on_complete: "Ответ принят. Откройте конверт №2."
    questions:
      - id: q1
        kind: mandatory       # mandatory | bonus | final
        type: form
        prompt: "Справка о погибшем"
        fields:
          - id: time
            type: time
            label: "Время констатации смерти"
            answer: { canon: "21:18", tolerance_min: 0 }
          - id: disease
            type: text
            label: "Хронические заболевания"
            answer: { canon: "астма", variants: ["бронхиальная астма"] }
        hints:
          - "…"   # уровень 1
          - "…"   # уровень 2
          - "…"   # уровень 3 — ответ
```

Правила:
- Путь единицы: `s<n>.<question.id>` или `s<n>.<question.id>.<field.id>`. Он участвует в криптографии — после выдачи QR и начала игр не переименовывать.
- `answer.canon` — канонический ответ (до нормализации; сборщик нормализует). `variants` — дополнительные допустимые формы. Для `time` — `tolerance_min` раскрывается в варианты. Для `choice`/`person`/`document` — ID; для `multi`/`persons` — список ID.
- `options` для `choice`/`multi`: список `{id, text}`. `pool` для `person`/`persons`: список ID персонажей или `default`.
- `kind: final` — только в этапе 4, порядок вопросов = порядок показа. Бонус этапа 4 (`kind: bonus`) задаётся на странице финала последним, по правилам финала.
- `leak_scan: false` у единицы — не искать её ответ в `dist/` (например, если время законно встречается в открытых материалах). Ставить осознанно.

Сборщик проверяет: у обязательного вопроса есть 3 подсказки; ID ответов существуют среди вариантов, персонажей или документов; у `form` есть поля; ответы `order` содержат все карточки ровно по разу.

## 6. `expertise.yaml`

```yaml
objects:                    # «опись»: всё, что можно передать в лабораторию
  - id: pillbox
    title: "Таблетница погибшего"
    from_stage: 1           # с какого этапа предмет есть в материалах (по умолчанию 1)
    ref: "1-09, поз. 17.3"  # необязательно: где упомянут; показывается в «Моих заявках»
    aliases: ["таблетниц", "пилюл"]   # основы для распознавания текста игрока (§ ниже)
  - { id: inhaler, title: "Ингалятор погибшего", from_stage: 2, aliases: ["ингалятор"] }
  - { id: lunchbox, title: "Контейнер для обеда", aliases: ["контейнер"] }   # пустышка: записей результатов нет
  - id: station_cam
    title: "Камеры железнодорожного вокзала"
    from_stage: 4
    aliases: ["камер вокзал"]
    params:                 # параметры запроса — у объекта
      - { id: date, type: date, label: "Дата" }
      - { id: time, type: time, label: "Время" }
      - { id: window, type: number, label: "Номер кассы" }
types:
  - id: chem
    title: "Химическое исследование"
    description: "Что исследуется и что можно узнать (раздел «Услуги»)."   # необязательно
results:
  - id: inhaler-chem
    object: inhaler
    types: [chem, content]  # любой из видов подходит
    stage: 2                # открывается с этапа 2
    bases: ["1-03", "1-08", "2-02"]
    doc: "2-01"             # ID документа из documents.yaml
    body: "documents/2-01.md"
  - id: station-video
    object: station_cam
    types: [video]
    stage: 4
    bases: ["3-07"]
    params_answer:
      date: { canon: "30.10.2026" }
      time: { canon: "14:37", tolerance_min: 7 }
      window: { canon: "2" }
    doc: "4-08"
    body: "documents/4-08.md"
```

(Предметы и названия в примере иллюстрируют формат, сюжетные данные — в самом файле.)

- **Опись.** `objects` — все предметы, которые команда может передать в лабораторию: «нужные» (у них есть результаты) и пустышки из описей и протоколов осмотра (без результатов). Предмета нет в `objects` — «нельзя передать в лабораторию»; есть, но запроса с такой комбинацией в `results` нет — «Экспертиза ничего не выявила» и штраф. `from_stage` — этап документа, где предмет появляется.
- **`aliases`** — список строк; каждая строка — одна или несколько **основ** через пробел (`"бутыл вод"` — оба слова должны встретиться в тексте игрока). Основа подходит слову, если оно с неё начинается: основа `таблетниц` ловит «таблетница», «таблетницу», «в таблетнице». Основа — не короче 3 символов; пишется строчными, «ё» как «е» (сборка нормализует сама). Название объекта (`title`) — тоже алиас, отдельно его перечислять не нужно. Одинаковые алиасы у разных объектов запрещены; алгоритм и проверки — `docs/02` §2а. Текст алиасов открыт вместе с этапом `from_stage`: в нём не должно быть ничего, что раскрывает сюжет.
- **`ref`** — необязательная строка «документ, позиция»; шаблоны разрешены.
- **`description`** вида исследования — короткий текст раздела «Услуги» сайта лаборатории; необязательный, открытый (лежит в `pack-1`).
- **Правило оснований.** Если у результата этапа `N` объект доступен раньше (`from_stage < N`), то все его основания — документы этапа `N` (иначе тот же запрос на раннем этапе ответил бы «ничего не выявила», а позже — заключением). Нарушение — ошибка сборки.
- Если у объекта есть `params`, у каждого его результата должен быть `params_answer` со всеми параметрами. Сборщик раскрывает допуски и перемножает варианты (следить за числом комбинаций: предупреждение при > 200 на результат).
- Результат без `doc` — «атмосферный»: короткий текст в `text`, документ не добавляется; штрафа за такой результат нет (он — найденная экспертиза).

## 6б. `lab.yaml` — сайт лаборатории «Призма»

Тексты разделов «Услуги» (условия), «О центре» и «Контакты» сайта `/lab/`. Бренд — `world.yaml: brands.lab` и `brands.lab_full`. Файл открыт (попадает в `dist/` как есть и проходит leak scan), поэтому только атмосфера вымышленной организации — без фактов дела.

```yaml
name: "{{ w.brands.lab }}"
full_name: "{{ w.brands.lab_full }}"
tagline: "…"
about: |
  …Markdown: история, аккредитация, как устроена работа с заказчиками…
accreditation: "…"
staff:                      # фоновые имена
  - { name: "…", role: "…" }
contacts: { address: "…", phone: "…", hours: "…", email: "…" }   # email необязателен
services_note: "Срок — 1 рабочий день; основание обязательно."
photos:                     # необязательно: галерея раздела «О центре», 1–3 снимка (больше — ошибка)
  - { file: "lab/building.jpg", caption: "…" }   # file — путь в media/ (.jpg, .jpeg, .png, .webp); caption необязательна
```

Сборка передаёт эти тексты (шаблоны уже подставлены) в шаблон `lab.html` переменной `lab_site` с теми же ключами плюс `about_html` (`about`, превращённый в HTML); рядом доступна переменная `brands` (бренды мира). `photos` попадают в `lab_site.photos` как `[{src, caption, alt}]`. Сайт лаборатории открыт, поэтому файл лежит в `dist/m/` как есть (открытое медиа; на него нельзя поставить ничего, что не должно быть публичным). Путь учитывается в `media_refs` (`photos[i].file`, контекст `open`); нет файла — предупреждение сборки (с `--release` ошибка), а снимок на сайте пропускается: ни сломанной картинки, ни пустого места. Описания видов исследований лежат в `expertise.yaml` (`types[].description`) и приходят в браузер в `pack-1`.

## 8. `pages/`

Одна папка на страницу: `pages/<slug>/page.yaml` (метаданные и структурированный контент: посты, записи, файлы облака) и при необходимости `*.md` для длинных текстов. Поведение страниц — `docs/04-pages.md`.

Общие поля `page.yaml`:

| Поле | |
|---|---|
| `slug` | = имя папки |
| `type` | необязателен; по умолчанию = `slug`. Выбирает схему, шаблон `site/templates/pages/<type>.html` и стили `assets/css/pages/<type>.css`. Страница с чужим slug (`news-fire`, `krug-volskaya`) обязана указать `type` |
| `doc` | документ из реестра. Необязателен: страница, на которую попадают только по ссылкам, задаёт `stage` |
| `stage` | этап страницы; обязателен без `doc`, с `doc` должен совпадать с этапом документа |
| `locked` | `false` — открытая; `true` — только по ссылке с ключом во фрагменте (QR или ссылка с другой страницы); `password` — по паролю из поля `password` (облако) |
| `qr_label` | подпись под QR-кодом (что видят игроки, без спойлеров). Только у страниц с `doc`; QR печатается только для них |
| `forbidden` | слова, которых не должно быть в тексте страницы (сборщик проверяет) |
| `gate` | необязательно, только `pacing` и только у `locked: true`: страница закрыта ради темпа, не тайны — шифруется и до своего этапа недоступна, но её текст leak scan секретом не считает (docs/02 §3.10) |

Типы и их поля (`brand` — из `world.yaml`, обычно `"{{ w.brands.… }}"`):

```yaml
# type: social — профиль в «Круге»; gromov тоже social
# stage: 2 + locked: true — профиль закрытого этапа (человек появляется в конверте 2): см. «Профили закрытых этапов» ниже
brand: "{{ w.brands.social }}"
stub: krug-private            # необязательно: заглушка до открытия этапа (по умолчанию krug-private)

**Пост «Круга»: `text`, `photo`, `audio`, `video`.** Нужно хотя бы одно из четырёх: пост может состоять только из голосового или только из видео (`text` тогда не пишут). Поля `file` и `duration` у `audio` обязательны, лишние ключи — ошибка. Файл голосового — такое же медиа, как фото: путь относительно `media/`, без `..`; нет файла — предупреждение сборки (с `--release` ошибка), в `dist/` у плеера нет `src`, и он показывает «Голосовое сообщение · 0:12» неактивным. Голосовое на закрытой странице шифруется вместе с остальными медиа (`/m/<hash>.bin`, ключ внутри зашифрованного фрагмента страницы). `transcript` — обычный текст (без Markdown и `{{ link() }}`-вёрстки; подстановки имён `{{ c.… }}` работают).

**Комментарий: `text` или `audio`.** У `comments[]` поле `text` необязательно, но нужен `text` или `audio` (или оба). `audio` — та же схема, что у поста (`file`, `duration`, `transcript?`), тот же плеер, только компактнее. Путь к файлу учитывается в `media_refs` как `posts[i].comments[j].audio.file`.

**Видео в посте: `video: {file, poster, duration}`.** Все три поля обязательны, лишние ключи — ошибка. `file` — только `.mp4`, `poster` — картинка (`.jpg`, `.jpeg`, `.png`, `.webp`), `duration` — «М:СС». Оба пути — относительно `media/`, как у фото (`<страница>/video-01.mp4`, `<страница>/video-01.jpg`). Видео и постер — обычные медиа: на открытой странице лежат в `dist/m/` как есть, на закрытой шифруются (`/m/<hash>.bin`, ключи внутри зашифрованного фрагмента страницы).
- *Формат:* контейнер MP4, видео H.264 (High или Main, `yuv420p`), звук AAC-LC, `-movflags +faststart` (индекс в начале файла — видео начинает играть до полной загрузки). Другие кодеки на части телефонов не играют.
- *Размер:* для телефона целиться в **≤ 15 МБ**: 720p (по длинной стороне), 25–30 кадров/с, видео около 1,5 Мбит/с, звук 96 кбит/с. Это примерно 1 МБ на 5 с, то есть ~15 МБ ≈ 75 с. Сборка предупреждает о файле больше 15 МБ. **На закрытой странице видео не больше 25 МБ — иначе ошибка сборки**: браузер скачивает и расшифровывает такой файл целиком в памяти (файл + расшифрованная копия + Blob). На открытой странице предела нет (играет потоком), но вес остаётся предупреждением.
- *Пример кодирования:* `ffmpeg -i in.mov -vf "scale=-2:720" -c:v libx264 -profile:v high -pix_fmt yuv420p -b:v 1500k -maxrate 2000k -bufsize 3000k -c:a aac -b:a 96k -movflags +faststart video-01.mp4`; постер — кадр оттуда: `ffmpeg -ss 1 -i video-01.mp4 -frames:v 1 -vf "scale=-2:720" -q:v 4 video-01.jpg` (до ~150 КБ).
- *Нет файла видео:* предупреждение сборки (с `--release` ошибка); в `dist/` нет ни `<video>`, ни `src`, ни кнопки — постер (если он есть) с надписью «Видео недоступно» и длительностью. Нет только постера — видео работает, но кадра-заставки нет (предупреждение).
- *Одинаковые файлы:* файлы с одинаковым содержимым под разными путями сборщик кладёт в `dist/m/` один раз; если хоть один из путей на открытой странице, файл открыт (он и так публичен).

**Фото в ленте** (`photo`, а также фото статей и карточек) грузятся лениво: `loading="lazy"`, `decoding="async"`; аватар и обложка профиля — сразу. На закрытых страницах расшифровка фото откладывается, пока оно не подойдёт к экрану. Для «Круга» с десятками фото: до ~200 КБ на фото (около 1080 px по длинной стороне).

**Фото в разделах: `site`, `cloud`, `news`, `lab.yaml`.** Все пути — относительно `media/`, без `..`; допустимы только картинки (`.jpg`, `.jpeg`, `.png`, `.webp`), иначе ошибка валидации. Файл учитывается в `media_refs`: на открытой странице (и в `lab.yaml`) он лежит в `dist/m/` как есть, на закрытой (в том числе облако за паролем) шифруется (`/m/<hash>.bin`, ключ внутри зашифрованного фрагмента) — как у остальных медиа. Нет файла — предупреждение сборки (с `--release` ошибка); в `dist/` нет ни `<img src>`, ни кнопки «крупно», вместо снимка — серая плашка «Здесь будет фото» (подпись остаётся). Все фото ленивые (`loading="lazy"`, на закрытых страницах расшифровка — по приближении к экрану), до ~200 КБ на фото.
- *Блок `photo` (`type: site`)*: `{kind: photo, file, caption?, wide?}`. `wide: true` — на всю ширину раздела, как обложка (на телефоне от края до края, 16:9 с обрезкой, на ноутбуке 21:9); без `wide` — в колонке текста, снимок целиком в своих пропорциях. `caption` — подпись под фото, она же подпись в окне просмотра. Крупно по нажатию.
- *Фото карточек* `cards.items[].photo`: превью 4:3, крупно по нажатию; нет файла — плашка без кнопки.
- *Папка облака `kind: photos`*: `{id, title, kind: photos, items: [{file, caption?, date?}]}` — не меньше одной записи, других полей (`columns`, `rows`, `participants`, `messages`, `body`) у такой папки нет, а `items` нет у остальных видов. Сетка квадратных миниатюр; под каждой — подпись и дата (`date` — ISO, показывается как ДД.ММ.ГГГГ; в окне просмотра подпись выглядит как «подпись · дата»).
- *Подпись к фото статьи* `article.photo_caption` (необязательна): `<figcaption>` под фото; без `photo` не показывается.
- *Галерея лаборатории* — `lab.yaml: photos` (§6б).

**Тип `video` (любой slug).** Поля: `slug` (любой идентификатор: `video` — закрытая страница 4-07, `archive` — открытая 1-15), `title`, `source`, `file {name, size, created, device, duration, resolution}`, `video` (путь к `.mp4` в `media/`), необязательный `poster` (путь к картинке `.jpg`, `.jpeg`, `.png`, `.webp` в `media/`; заставка плеера), необязательный `clues` (список меток улик из `filename`, `created`; по умолчанию обе, у страницы без улик — `clues: []`). Доступ — как у всех страниц: `locked: false` — открытая, иначе ключ в QR. Нет файла видео или постера — предупреждение сборки (с `--release` ошибка), на странице плашка «Здесь будет видео» или плеер без заставки.

**Тип `mail` (любой slug; решение автора 25.10.2026).** Почтовый ящик вымышленного почтового сервиса — «выгрузка ящика по запросу следствия»: игроки читают рабочие и личные письма и сами замечают среди них странную переписку. Схема — `MailPage` в `engine/models.py`, поведение — `docs/04` «`mail`».

| Поле | |
|---|---|
| `type` | `mail` (обязательно: slug любой, например `mail-zavyalov`) |
| `stage`, `doc`, `locked` | как у всех страниц; обычно `locked: true` — ключ в QR или ссылка с другой закрытой страницы |
| `brand` | название почтового сервиса, по умолчанию «Почта»; обычно `"{{ w.brands.mail }}"` (ключ `brands.mail` добавляет сценарист в `world.yaml`) |
| `account` | владелец ящика: `person` (ID персонажа) **или** `name` — ровно одно, и `address` |
| `notice` | необязательно: служебная плашка над ящиком, например «Выгрузка ящика по запросу № … от …» |
| `folders` | список названий папок в порядке меню; по умолчанию `["Входящие", "Отправленные"]`; без повторов |
| `threads[]` | цепочки писем (не меньше одной), см. ниже |

Цепочка `threads[]`: `id` (латиница, уникален в странице), `folder` (одно из `folders`), `subject`, необязательный `participants` (список адресов; по умолчанию «с кем» в списке — отправители кроме владельца, а если писал только владелец — «Кому: …» получатели), `messages[]` (не меньше одного).

Письмо `messages[]`: `from` (адрес), `to` (список адресов, не меньше одного), `date` (ISO `ГГГГ-ММ-ДДTЧЧ:ММ`, секунды необязательны), `body` (Markdown: абзацы через пустую строку, цитата `> …`, ссылки `[текст]({{ link('slug') }})`), `attachments[]` (необязательно), `read` (по умолчанию `true`; `false` — письмо не прочитано владельцем: цепочка в списке жирным, у письма метка «Не прочитано». Это часть выгрузки — при открытии статус не меняется).

Адрес (`from`, `to[]`, `participants[]`): `address` и необязательное имя — `person` (персонаж; показывается «Имя Фамилия») или `name`, не больше одного; без имени показывается только адрес. Домен — только вымышленный: адрес на домене настоящего почтового сервиса или ведомства (`gmail.com`, `mail.ru`, `yandex.ru`, `gosuslugi.ru` …, список — `REAL_MAIL_DOMAINS`) — ошибка валидации.

Вложение `attachments[]`: `name` (имя файла), `size` (строка как в почте: «120 КБ», «2,1 МБ») и не больше одного из: `media` — картинка в `media/` (`.jpg`, `.jpeg`, `.png`, `.webp`): миниатюра и просмотр крупно, на закрытой странице шифруется вместе со страницей (как фото в «Круге»); `page` — ссылка на страницу (правила ссылок — как у `page:` везде); ни того ни другого — просто строка с именем файла (не нажимается). Нет файла `media` — заглушка «Здесь будет вложение» (предупреждение сборки).

Цепочки в списке — по дате последнего письма, новые сверху; письма в цепочке — по дате, старые сверху (порядок в YAML не важен). Тексты писем закрытого ящика — секрет для leak scan (обычный режим, docs/02 §5а): фраза, дата и время из письма на открытой странице — утечка. `pinned`, `starred`, `stub` у почты нет.

profile: { name: "Женя Соколова", avatar: "kadr-zhenya/avatar.jpg", posts: 112, followers: 340, follows: 215 }

# в pages/inna/page.yaml — профиль: 
#   followers: 214
#   following:
#     - { person: oleg, page: kadr-oleg }
#     - { name: "Женя Соколова", page: kadr-zhenya }
```

(Имена и slug-и примера условные — не сюжет.) Профиль «Кадра» этапа 3 и дальше, на который ссылаются страницы этапа 2, обязан иметь `stub:` — заглушку `photo_stub` (обычно того же человека, этап 2): до открытия этапа ссылки ведут на неё.

**Профили закрытых этапов (`social`, `photo`; docs/02 §3.10).** Профиль с `stage: N ≥ 2` (без `doc`) и `locked: true` шифруется, как страница по QR. Ссылки на него — с открытых страниц и со страниц этапов раньше `N` (друзья, авторы комментариев, `{{ link() }}` в постах, карточки сайта, поиск «Круга») — сборка ставит на заглушку (`stub`; у «Круга» по умолчанию `krug-private`) с `#to=<slug>`, а не на сам профиль; ключ профиля попадает только в пакет этапа `N`. Когда команда открыла этап `N`, на её устройстве те же ссылки ведут на настоящий профиль. Сценаристу: чтобы перевести человека из конверта 2 на этап 2 — `stage: 2`, `locked: true` и `gate: pacing` у его `krug-…`; ссылки на него в чужих страницах менять не нужно. Ограничения: профиль `social`/`photo` с `stage ≥ 2` и `locked: false` — ошибка; `stub` должен быть страницей `social_stub` или `photo_stub`; страницы других типов (сайт, статья) по-прежнему нельзя ссылать с открытых страниц, если они этапа 2+. С `gate: pacing` тексты профиля leak scan не проверяет (это темп, не тайна; проверяется только, что ключ не утёк). Без него тексты профиля — секрет: фраза, дата и время из него на открытой странице — утечка (законные повторы — `settings.leak_public_ok`).

**Ссылки.** В структурных полях — `page: <slug>`; в Markdown и строках — `{{ link('slug') }}`. Для открытой страницы это `/p/<slug>/`, для закрытой по ключу — `/p/<slug>/#k=<ключ>` (формат QR). Сборка проверяет: страница-цель есть; `stage` цели ≤ `stage` источника (этап — у документа `doc` или поле `stage`); из открытой страницы — только на страницы этапа 1. Ошибка — сборка и `check` падают. Предупреждение: страница без `doc` и без входящих ссылок. Автор комментария или друг без `page` ведёт на `krug-private`; логотип «Круга» — на `krug`: обе страницы обязательны, если есть хоть один профиль «Круга».

**Ключи.** Для новых закрытых страниц ключ дописывается в `engine/salts.lock.json` при сборке; существующие ключи не меняются.

**Тексты подвала сервисов** — `pages/_brands.yaml` (необязателен), общий файл на бренд:

```yaml
services:
  social:            # ключ бренда из world.yaml → brands: social, photo, news, pharma, cloud, mail
    about: "…"       # «О сервисе»; абзацы — через пустую строку
    rules: "…"       # «Правила»
    help: "…"        # «Помощь»
```

Тип страницы → сервис: `social*` → `social`, `photo`, `photo_stub` → `photo`, `news*` → `news`, `pharma`, `cloud`, `mail` → `mail` (раздел `services.mail` необязателен: без него у почты подвала нет). У `call`, `video` и `site` подвала сервиса нет (у `site` — разделы и строка `footer`). Тон служебный, без сюжета, имён и дат.

## 8а. `paper/` — бумажные документы конвертов

Тексты документов `kind: paper` из `documents.yaml` — по файлу на документ: `paper/<id>.md`. Только для
печати (`python -m engine paper` → `print/paper/`): сайт их не публикует, а `check` проверяет, что ни
одна последовательность из 4 слов этих текстов не попала в `dist/` (как для закрытых текстов).

```markdown
---
id: "1-07"                 # = имя файла; документ kind: paper из documents.yaml
form: program              # бланк: site/templates/print/paper/<form>.html
title: "{{ w.play.title }}"  # необязательно; по умолчанию — название из documents.yaml
stage: 1                   # необязательно; если указан — должен совпадать с documents.yaml
date: "{{ w.dates.premiere }}"   # необязательно; ISO-дата печатается как 10.11.2026
place: "{{ w.city }}, {{ w.theater.address }}"
signed:                    # подписи внизу документа
  - { role: "{{ c.kovalev.role }}", name: "{{ c.kovalev.short() }}" }
media: ["lab/photo1.jpg"]  # изображения из media/ (только .jpg .jpeg .png .webp .svg)
qr: true                   # по умолчанию true, если у документа есть page (QR-код страницы в углу)
pages_hint: 1              # ожидаемое число страниц A4 — сверяется с PDF, расхождение в отчёте
meta:                      # свободный словарь для бланка
  author: "{{ w.play.author }}"
---
## Действующие лица и исполнители

| Роль | Исполнитель |
|---|---|
| {{ w.play.role_main }} | {{ c.voroncov.short() }} |
```

- Front matter и тело — шаблоны (`c`, `w`, §1); даты в front matter — в кавычках.
- Тело — Markdown с таблицами; сырой HTML разрешён (это печать, не сайт). Тело может быть пустым
  (например, у `form: chat`).
- `form` — имя бланка; список расширяемый: новый бланк = новый файл `site/templates/print/paper/<form>.html`.
  Сейчас есть: `protocol`, `report`, `inspection`, `phototable`, `inventory`, `forensic`, `ambulance`,
  `plan`, `program`, `journal`, `memo`, `certificate`, `ticket`, `estimate`, `registry`, `pharmacy`,
  `press`, `letter`, `note`, `chat`.
- `form: chat` — в документ вставляются «скриншоты» телефона из `chats/<id>.yaml` (файл обязателен).
- `form: protocol` — каждый протокол опроса — раздел `## N. …`; сразу после заголовка — метка
  `<!-- person: <id> -->` (id из `characters.yaml`), у одиночного протокола — первой строкой текста.
  По метке в шапку протокола ставится фото персонажа (`photo` или `portraits/<id>.jpg`, если файл
  есть); разделы печатаются каждый с новой страницы (при `print.duplex` — с нового листа).
  Поля протокола печатаются «МЕТКА: значение» рядом с фото: у одиночного протокола — из `meta.person`
  (строка или список; «ФИО, 1981 г. р., должность» делится на «Опрошен(а)», «Год рождения», «Сведения»),
  `meta.person_label` (по умолчанию «Опрошен(а)»), `meta.by` (метка `meta.by_label`, по умолчанию
  «Опросил»), `meta.present` — кто присутствовал (метка «При опросе»), `place`, `date`/`meta.start`/`meta.end`;
  у протоколов с разделами (1-08) — из блока `.proto__fields` (макрос `head()` в тексте: поля
  `fld__label`/`fld__value`; «Присутствовал(а)» печатается как «При опросе»). Реплики «**Вопрос:**» /
  «**Ответ:**» печатаются с фамилией опросившего (из «Опросил»: слово перед инициалами) и опрашиваемого
  (из метки `person`); абзац без метки между репликами — продолжение реплики; курсивные абзацы
  `*…*` после последней реплики — под меткой «Примечание опросившего:» (абзац, начинающийся с
  «Отметка …:», — под своей меткой). Курсивные абзацы между репликами — обычным текстом.
- `meta.note` (протокол с разделами) — текст сводного листа «Опись протоколов», который печатается перед
  протоколом № 1: таблица разделов (№, ФИО, дата и время, место — из полей) и под ней `meta.note` под
  меткой «Примечание». Без `meta.note` там печатается вступление документа (текст до первого `## `).
  Заголовок сводного листа — `meta.cover_headline` (по умолчанию «Опись / протоколов»), подпись счётчика
  на нём — `meta.count_label` («Протоколов: 6»); заголовок листа каждого раздела — в единственном числе
  `meta.section_headline` (без него — `meta.headline`, по умолчанию «Протокол / опроса»).
- `meta.body_chart.marks: []` — схема тела без отметок, под ней только `note`.
- `meta.headline` — свой крупный заголовок бланка (docs/05 §4): строка, строки — через «/» или перевод
  строки («Протокол / допроса»), или список строк. Без него заголовок берётся из названия документа,
  если оно короткое («Протокол повторного опроса» → «ПРОТОКОЛ / ПОВТОРНОГО ОПРОСА»), иначе — умолчание
  бланка («ЗАКЛЮЧЕНИЕ / СУДМЕДЭКСПЕРТА», «РАПОРТ», «ВЫПИСКА / ИЗ РЕЕСТРА» …; `engine/paper.py: HEADLINES`);
  тогда полное название печатается мелко в правом мини-блоке.
- Средняя точка «·» как разделитель запрещена и в текстах бумаги (CLAUDE.md): при печати она заменяется
  запятой, а `paper` выводит предупреждение с именем файла — поправить текст.
- `meta.brand` — айдентика бланка (эмблема, цвет, шапка; docs/05 §4), если не угадывается по `meta.org`:
  `so`, `police`, `sme`, `smp`, `theater`, `admin`, `pharmacy`, `registry`, `railway`, `llc`, `fund`, `lab`,
  `private`, `none`.
- `form: forensic` — `meta.cells: [{label, value, wide}]` — поля заключения «МЕТКА: значение» (ФИО, год
  рождения, дата смерти, № трупа…; `wide: true` — своей строкой, короткие — по несколько в строку); `meta.body_chart: {marks: [{zone, label}], note}` —
  схема тела спереди и сзади: `zone` — `front`, `back`, `head-front`, `head-back`, `neck-front`, `neck-back`,
  `chest`, `abdomen`, `back-upper`, `back-lower`, `legs-front`, `legs-back` (штриховка и номер), `label` —
  подпись в легенде, `note` — примечание под схемой. Только сведения, которые есть в тексте заключения.
  Неизвестная зона — пометка в отчёте `paper` и ошибка `--release`.
- Фото-карточки персонажей (`print/paper/cards-<N>.pdf`) строятся из меток `<!-- person -->` протоколов
  сами: роль — из строки «Опрошен(а)» первого протокола человека (после «… г. р., », у протокола из
  `meta.person` без года — вторая строка). Отдельной разметки не нужно.
- `meta` понимают все бланки: `org` — организация вместо умолчания бланка (строка или список
  строк, мелко в мини-блоке шапки; по умолчанию у протоколов и рапортов — `w.police.department`,
  у программки, плана, журналов и служебных записок — `w.theater.full`), `headline`, `number`,
  `to` (поле «Кому:»), `from` («От кого:»), `subtitle` (тема строкой под шапкой), `captions`
  (подписи к `media` по порядку); остальные ключи — для конкретного бланка (`author` у программки).
  Только вымышленные организации.
- Проверки: `id` есть в `documents.yaml` и это `kind: paper`, совпадает с именем файла, без дубликатов;
  `stage` совпадает; бланк существует; `qr: true` только у документа с `page`; медиа — относительный
  путь в `media/` с допустимым расширением изображения; все шаблоны рендерятся. Ошибка — файл, путь
  до поля, что не так.
- `TODO(content)` в front matter (с путём до поля) и в тексте (с номером строки) попадают в список
  заглушек. Нет файла для бумажного документа — заглушка «нет текста бумажного документа»
  (`missing-paper`): при печати — страница «Документ 2-05: текст не готов», в `paper --release`,
  `build --release` и `release` — ошибка.

## 9. Заглушки

`TODO(content): описание` в любом тексте допустим. Сборка с заглушками проходит, но печатает их список. Флаг `python -m engine build --release` превращает любую заглушку в ошибку.
