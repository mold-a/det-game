# 06. Тестирование и самопроверка

## 1. Кросс-языковые векторы — `tests/vectors/`

| Файл | Что | Кто генерирует | Кто проверяет |
|---|---|---|---|
| `normalize.json` | Вход, тип, ожидаемый выход (или `null`) — не меньше 60 случаев | Пишутся руками | `pytest` и `npm run test:js` |
| `crypto.json` | PBKDF2, HKDF и AES-GCM: входы и ожидаемые байты; контейнеры, зашифрованные Python | `python -m engine vectors` | `npm run test:js` расшифровывает и сверяет |
| `lab-match.json` | Распознавание объекта лаборатории: токены, синтетические каталоги и ввод → `ok` / `ambiguous` / `none` (падежи, «ё», пунктуация, многословные алиасы, повтор основы, символы вне BMP, порядок в `ambiguous`) | `python -m engine vectors` (ожидания пишутся руками в `engine/vectors.py`, генератор сверяет с `labmatch.py` и падает при расхождении) | `tests/test_labmatch.py` и `tests/js/labmatch.test.mjs` |

Правило: любое изменение `normalize`, `labmatch` или `crypto` → обновить векторы → обе стороны зелёные.

## 2. Python (`pytest`)

- Нормализация по векторам, плюс граничные случаи времени и дат.
- Криптография: шифрование ↔ расшифровка, неверный ключ и неверный AAD → ошибка.
- Валидация контента: на испорченных копиях `content/` (нет подсказки, неверный ID ответа, дубликат ID, опечатка в шаблоне) сборка падает с понятным сообщением.
- Распознавание объекта (`tests/test_labmatch.py`): векторы `lab-match.json` и актуальность файла; ключ `(pos, -score)`; повтор основы; многословные алиасы; падежи; «ё»; пунктуация; пустая строка; `ambiguous` в порядке каталога; название как алиас.
- Каталог и правила лаборатории (`tests/test_lab_catalog.py`): `aliases`, `ref`, `description` в `LabCatalog`; объект лежит в пакете своего `from_stage`; на испорченных копиях `content/` сборка падает при короткой основе, повторяющемся алиасе, не узнающем себя названии, нарушении правила оснований; предупреждение об общей короткой основе; `lab.yaml` в контексте `lab.html`.
- Склонение: таблица форм для всех персонажей строится без исключений.
- `salts.lock.json`: повторная сборка не меняет соли и ключи страниц; новая единица дописывает соль.

## 3. Самопроверка сборки — `python -m engine check`

Обязательна после каждой сборки, падает при любой ошибке.

1. **Прохождение.** Как в браузере (FORMATS §2.4): порядок вопросов, `kind` и `unit.type` берутся из расшифрованного пакета; правильные ответы → записи пакета → ключ следующего этапа → пакет расшифровывается. Структура пакета сверяется с контентом (порядок вопросов и полей, `kind`, типы), карточки `order` в пакете перемешаны и ≠ ответу.
2. **Все варианты.** Каждый допустимый вариант каждой единицы проверяется как верный и даёт тот же канон.
3. **Неверные ответы.** Для каждой единицы 5 правдоподобных неверных ответов (соседние варианты списка, время ±(допуск+1) мин, пустая строка) — не проходят.
4. **Экспертизы.** Проверки каталога из `docs/02` §2а (основы, алиасы, название узнаёт само себя, правило оснований; общая короткая основа — предупреждение). Каталог в пакетах совпадает с контентом (`title`, `aliases`, `ref`). Объект каждого результата определяется как в браузере — по названию из пакета через `resolve_object` среди объектов пакетов `1…N`, ключ выводится по найденному `id`. Каждая запись открывается каждым допустимым основанием и не открывается до своего этапа и с неверным параметром. Исчерпывающе: для каждого объекта любой вид × любой документ вне допустимых не открывает ни одной записи ни на одном этапе.
5. **Страницы.** Каждая закрытая страница расшифровывается своим ключом; облако — паролем из контента.
6. **Развязка.** Расшифровывается ключом этапа 4.
7. **Leak scan.** Во всех текстовых файлах `dist/` (любое расширение, кроме двоичных: `*.bin`, шрифты, изображения, аудио, видео) и в **именах** всех файлов не встречаются:
   - канонические ответы и варианты единиц типов `text`, `time`, `date`, `number` (кроме `leak_scan: false`), даты — и в виде `ДД.ММ.ГГГГ`;
   - значения `params_answer` экспертиз; строки `settings.leak_watchlist`; пароль облака; названия документов этапов 2–4;
   - **шинглы** — все последовательности из 4 токенов `base()` по всему тексту (не только начало): подсказок, текстов пакетов этапов 2–4 (письма, вопросы, варианты, документы), результатов экспертиз, развязки и закрытых страниц. Тексты берутся из расшифрованного `dist/` — так, как их видит игрок (шаблон страницы, даты в формате показа). Не иголки: шинглы только из служебных слов и подписей подвала сервисов, заглушки «Здесь будет …», статический текст шаблонов `site/templates` и строк интерфейса `texts.js`, оболочка и наименования (бренды, шапка, логин облака, подвалы сервисов, названия объектов каталога и документов этапа 1) и фразы из `settings.leak_public_ok`. Проза открытых страниц (`locked: false`) и текста этапа 1 секретные шинглы **не отбеливает**: фраза из закрытого текста на открытой странице — ошибка (docs/02 §5а);
   - нейтральные примеры из интерфейса не должны совпадать с ответами (проверяется отдельно).
   Значения короче 4 символов не ищутся и перечисляются в отчёте. Поиск — по целым словам (границы токенов), в сыром виде и после `base()`; JSON-экранирование `\uXXXX` и HTML-сущности раскрываются перед поиском; поля `n` и `c` зашифрованных контейнеров, соли и ключи пропускаются — base64url даёт ложные совпадения.
   Открытый текст `pack-1` (его ключ публичный) сканируется иголками этапов 2–4; в нём только персонажи из пулов вопросов этапа и только поля `id`, `full`, `short`, `photo`.
   Плюс: ни один медиафайл, на который ссылается только зашифрованный контент, не лежит открытым **нигде** в `dist/`. Комментарии `/* … */` из CSS при копировании `site/assets` удаляются (кроме `/*! … */`).
8. **Заглушки.** Список `TODO(content)`; с `--release` — ошибка.
9. **Отчёт.** Таблица: этапов, единиц, вариантов, экспертиз, страниц, размер `dist/`, самый большой файл.
10. **Имена буквами.** Защита от поломки при подстановке настоящих имён (`import-cast`, P09): в **сырых** (нерендеренных) текстах `content/` — `stages.yaml`, `documents.yaml`, `expertise.yaml`, `finale.yaml`, `documents/*.md`, `pages/**/*.yaml` и `*.md`, `chats/*.yaml`, `paper/*.md` — не должно быть имён персонажей с `cast: true`, вписанных буквами вместо `{{ c.<id>.… }}`.
   - Смотрятся только значения строк YAML и тела Markdown (и значения front matter); ключи, комментарии YAML и всё внутри `{{ … }}`, `{% … %}`, `{# … #}` пропускаются.
   - Совпадение — целые слова (сравнение через `base()`: регистр, ё/е), каждое слово найденного — с заглавной буквы; ищутся все падежные формы (`engine/names.py`) фамилии, имени, отчества и `familiar` (в падежах тоже), сочетания «Фамилия Имя Отчество», «Имя Отчество», «Имя Фамилия», «Фамилия Имя» — по самому длинному совпадению.
   - Исключения (`engine/hardnames.py`): одиночное имя, отчество или `familiar`, совпадающее с обычным словом (`COMMON_WORD_NAMES`: «Вера», «Надежда»…) или со словом из строк `world.yaml` (роль «Нина» в пьесе) — во всех падежах; фамилии строже — только явный `SURNAME_EXCEPTIONS`; сочетания — без исключений. `cast: false` не ищутся (их ФИО поглощается целиком); части имени с `TODO(content)` и строки текста с `TODO(content)` не учитываются.
   - Вывод: `файл:строка: найдено «…» → {{ c.<id>.… }}` (несколько кандидатов — через «или», другие подходящие падежи — в скобках). Без `--release` — предупреждение (строка таблицы OK, список «Предупреждения»); `check --release` и `release` — ошибка.

## 4. JS (`npm run test:js`)

- Нормализация по `normalize.json`.
- Распознавание объекта лаборатории по `lab-match.json` (`tests/js/labmatch.test.mjs`): те же токены и те же ответы, что у Python.
- Расшифровка контейнеров из `crypto.json`.
- Модуль состояния: начисления и списания, повторный неверный ответ без штрафа, автоподсказка после N ошибок, экспорт → импорт → то же состояние.
- Работа без `localStorage` (имитация исключения) — игра идёт в памяти.

## 5. Сквозные тесты (Playwright, `tests/e2e/`)

Против `python -m engine serve`. Ответы тесты берут из `tests/.answers.json` (`python -m engine dump-answers`): в `content/` ответы — шаблоны Jinja2, Node их не отрендерит.
- **Полное прохождение** правильными ответами: этап 1 → 4 → финал → развязка; итоговый счёт совпадает с ожидаемым.
- **Ошибки и подсказки:** 3 неверные попытки → автоподсказка, покупка уровней 2 и 3, счёт в журнале верный.
- **Лаборатория:** объект вводится текстом (`objectTitle` из `.answers.json`). Предмета нет в описи → «нельзя передать в лабораторию», без штрафа и без записи в «Мои заявки»; предмет из описи без записи → «Экспертиза ничего не выявила», −5; повтор без штрафа; запрос с основанием → заключение в «Моих заявках» и в выборе типа `document`; неоднозначный ввод → уточнение без штрафа.
- **Перезагрузка** посреди этапа 3 → прогресс на месте.
- **Финал:** после ответа вернуться нельзя; развязка показывается.
- **Закрытые страницы:** с ключом — открываются, без ключа и с испорченным — «Ссылка повреждена».
- **Вёрстка:** скриншоты всех страниц на 360, 768, 1280 px, проверка отсутствия горизонтальной прокрутки.
- **Производительность:** время одной проверки ответа и вывода ключа этапа при CPU throttling ×4 — в отчёт.

- [ ] Видео и аудио воспроизводятся на iPhone и Android.
- [ ] Полное прохождение человеком, который не знает сюжета, или хотя бы автором с таблицей ответов.
- [ ] Аварийный конверт распечатан и запечатан.
